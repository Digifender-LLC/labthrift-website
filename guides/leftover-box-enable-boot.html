Notes / Faster network / Make sure house jobs start after every reboot

Written 28 Aug 2026. This is a how-to, not a product card.

Make sure house jobs start after every reboot

Before you buy a monitoring box, check that Pi-hole and the house share are set to start when the computer boots.

You restarted Pi-hole or Samba by hand. Ads are gone again. The share is back. Then the computer reboots for weekly fixes, and the house jobs stay off. That is not a broken computer. A job can be running right now and still not be set to start on the next boot. You are not buying a monitoring box for this look.

Skip until SSH works

If you cannot log in from the couch, stop. That is SSH from the couch. If the computer just came back up and you have not checked the house jobs yet, start with after a reboot, check the computer still does its jobs. This note assumes you can type commands on the computer from the couch.

What this is

systemctl is-active asks whether a job is running right now. That is the morning check in after a reboot, check the computer still does its jobs. systemctl is-enabled asks a different question: will this job start by itself the next time the computer boots? Enabled means yes. Disabled means you have to start it by hand again. You want the house jobs enabled.

Ask if the house jobs start on boot

SSH in from the couch, then run:

systemctl is-enabled pihole-FTL

systemctl is-enabled smbd

You want enabled on both. SSH is usually already enabled on Debian or Ubuntu Server:

systemctl is-enabled ssh

Some computers call that unit ssh.service or sshd. If you see the unit was not found, try the other short name. If Pi-hole or Samba was never installed, skip that line. Install first: the first useful thing on the computer and a file share on the computer.

If a house job says disabled

Turn it on for this boot and every later boot:

sudo systemctl enable --now pihole-FTL

or

sudo systemctl enable --now smbd

The --now part starts it immediately. Then check again:

systemctl is-enabled pihole-FTL

systemctl is-active pihole-FTL

You want enabled and active. Same for smbd. If a name showed up as failed instead, that is see if any house jobs failed to start. Don't edit unit files tonight.

What next

Leave it. The morning checklist stays after a reboot, check the computer still does its jobs. Failed starts stay see if any house jobs failed to start. Ads that came back stay when ads come back, check the ad block. A vanished share stays when the house share disappeared, check the computer. Skip a monitoring box for this look.

Skip

  • Skip this note if SSH from the couch does not work yet. That is SSH from the couch.
  • Skip if Pi-hole or the house share was never installed.
  • Skip buying a monitoring box because one reboot left a job off.
  • Skip editing unit files tonight.
  • Skip opening SSH to the internet.
