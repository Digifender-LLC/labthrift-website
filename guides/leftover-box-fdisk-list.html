Notes / File storage / Peek at partition tables with fdisk

Written 2 Sep 2026. This is a how-to, not a product card.

Peek at partition tables with fdisk

After udevadm shows disk properties, use a look-only fdisk -l so you see the partition table layout, sizes and slice names, without creating, deleting, or rewriting anything.

A partition table is the map of how a disk is sliced into named pieces. fdisk -l prints that map as text. Tonight you only read. You don't enter the interactive editor, write a new table, format a slice, or wipe a disk.

Skip until SSH works

If you cannot log in from the couch yet, stop. That is SSH from the couch. Partition tables don't help a login that fails.

If you only need the list of disks and USB sticks, that is see disks and USB sticks on the computer (lsblk). If you only need which folders are already attached, that is see which folders are already attached (findmnt). If you only need labels and UUIDs printed as text, that is read disk labels and UUIDs (blkid). If you only need filesystem UUID paths, that is see stable disk names by UUID. If you only need hardware-style fixed names, that is see stable disk names by hardware id. If you only need udev's property scrapbook, that is peek at disk details with udevadm. If you only need room left on a path, that is see if the computer still has room (df).

What this is

fdisk is an old Linux tool that can both list and edit partition tables. The list switch is -l (the letter L). That is the only mode you use tonight.

Here is the one jargon split for tonight: lsblk shows a friendly tree of disks and slices. fdisk -l shows the same idea in a more technical printout: disk size, partition table type (often GPT or DOS/MBR), and each slice's start/end/size. Same computer, table-style peek. Still no write, format, or wipe.

Practice: list the tables (look only)

SSH in from the couch. Then ask for the list:

fdisk -l

If you see permission denied, try once with admin rights (still look-only):

sudo fdisk -l

You should see blocks of text, one per disk, naming the device (often /dev/sda or /dev/nvme0n1), the disk size, the partition table type, and a table of slices with names like /dev/sda1. In plain English: fdisk is reading the map that already lives on the disk, not drawing a new one.

Optional: limit the printout to one disk you already trust from lsblk:

sudo fdisk -l /dev/sda

Swap /dev/sda for the name on your box. Don't invent one. Home-safe look only. Don't type interactive letters like n, d, or w. Don't format, wipe, remount, or edit fstab tonight.

Optional: after you plug in a USB for backup

Plug the stick into the computer. Run lsblk so you know today's letter, then run sudo fdisk -l on that whole-disk name (for example /dev/sdb, not a slice like sdb1). You should see a small table for the stick. Compare with blkid if you want LABEL/UUID next, or with udevadm if you want model/serial. If you need the mount map, that is see which folders are already attached. The backup job, once a path is live, is a backup of the house folder.

Useful extras, still a look

Skip interactive fdisk (no bare fdisk /dev/… menu). Skip n / d / w / o / g as the lesson. Tonight: -l only.

Look-only parted -l is its own note: peek at partition layout with parted. Skip interactive parted write verbs, cfdisk, sfdisk, gdisk, mount, umount, rewriting disks, dd, shred, format, or rewriting fstab. Those are not this note.

What this is not

This is not lsblk. That lists disks and USB sticks by name: see disks and USB sticks on the computer. It is not findmnt. That shows which folders are already attached: see which folders are already attached. It is not blkid. That prints LABEL, UUID, and TYPE as text: read disk labels and UUIDs. It is not by-uuid. That lists filesystem UUID paths under /dev/disk/by-uuid: see stable disk names by UUID. It is not by-id. That lists hardware-style names under /dev/disk/by-id: see stable disk names by hardware id. It is not udevadm. That prints udev's property list: peek at disk details with udevadm. It is not parted -l. That is a second layout printout: peek at partition layout with parted. It is not disk-space (df). That shows how full a mounted path is: see if the computer still has room. It is not disk, which focuses on how big the main disk already is: see how big the computer disk already is. It is not USB-disk, a shorter "did the stick show up?" check: see if the USB backup disk showed up. It is not the backup copy itself: a backup of the house folder.

Skip

  • Skip if SSH still fails. Finish SSH from the couch first.
  • Skip lsblk, findmnt, blkid, by-uuid, by-id, udevadm, disk-space, or total disk size as tonight's job if you only came for the look-only fdisk -l peek. Those notes already exist.
  • Skip interactive fdisk and any write letters (n/d/w/…). List mode only.
  • Skip interactive parted write verbs here. Look-only parted -l is peek at partition layout with parted. Skip cfdisk/sfdisk/gdisk as the lesson, and skip mount/umount, rewriting disks, dd, shred, format, and rewriting fstab.
  • Skip buying a NAS because a GPT or DOS line looks unfamiliar.
  • Skip awk/sed/install as new pages this cycle, screen, tmux, and port 22 forwarding.
  • Skip opening SSH to the internet. That is keep the computer on the house network. Don't forward port 22.
