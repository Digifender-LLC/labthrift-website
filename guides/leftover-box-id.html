Notes / Faster network / See user number and groups

Written 31 Aug 2026. This is a how-to, not a product card.

See user number and groups

After whoami, print user number and groups with id so sudo and file ownership make sense. You don't need extra software for this.

See the login name printed who you are. Tonight you look up your numbers and groups: id. Id prints uid, gid, and groups on one line. You are still only practicing in home on the computer. It does not need extra system software, htop, Grafana, or a NAS for this one job.

Skip until SSH already works

SSH from the couch should already get you a prompt. If login name only is what you want, that is see the login name. If who is sitting there is what you want, that is see who is on the computer right now. If sudo is what you want, that is see if your login can use admin commands. If old accounts are what you want, that is see if the computer still has old login accounts.

What this is

id prints user number and groups. You type id. uid is the user number. gid is the group number. groups is the list. id -u prints only the user number. It is not whoami. Whoami prints the login name. It is not sudo. Sudo asks if this login can use admin commands. You can stop at id.

Practice id in home

SSH in. Make sure home is where you sit:

pwd

You want a path that ends in your login name. If not:

cd ~

Ask for user number and groups:

id

You want one line with uid, gid, and groups, then the prompt back. That is enough for tonight. Practice only in home.

Debian and Ubuntu usually already have id. Don't make apt the job. If id is missing:

sudo apt install coreutils

Then stop. That install is not the lesson.

Useful extras, still home only

Optional: user number only:

id -u

Don't make -u required. You can stop at id.

What this is not

This is not whoami. That is see the login name. It is not who. That is see who is on the computer right now. It is not sudo. That is see if your login can use admin commands. It is not a password change. That is change the login password. It is not uname. That is see kernel name and architecture. It is not opening SSH to the internet. That is keep the computer on the house network. Don't forward port 22.

What next

Need login name only? See the login name. Need kernel name? See kernel name and architecture. Need HOME and PATH? See HOME and PATH. Keep SSH on the house network: keep the computer on the house network. Don't forward port 22.

Skip

  • Skip if SSH still fails. Finish SSH from the couch first.
  • Skip whoami, who, sudo, and uname as tonight's job. Those pages already exist.
  • Skip editing /etc/passwd or /etc/group tonight. Tonight you take a look.
  • Skip files under /etc, SSH folders, or paths you don't own. Practice only in home.
  • Skip rm -rf. Careful delete only: delete a file carefully.
  • Skip opening SSH to the internet so you can do this from a coffee shop. That is keep the computer on the house network. Don't forward port 22.

Sources

Debian: id(1). Ubuntu: id(1). Official pages only. For the login, see SSH from the couch. For login name only, see see the login name.
