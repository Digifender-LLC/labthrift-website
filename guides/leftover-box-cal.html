See the month on a calendar

After date, print this month as a grid with cal. You don't need extra software for this.

See what time the computer thinks it is printed the clock line. Tonight you print a month grid: cal. Cal prints this month. You are still only practicing in home on the computer. It does not need extra system software, htop, Grafana, or a NAS for this one job.

Skip until SSH already works

SSH from the couch should already get you a prompt. If the clock read is what you want, that is see what time the computer thinks it is. If the clock zone is what you want to set, that is set the clock to your house. If how long a command took is what you want, that is see how long a command took.

What this is

cal prints a month grid. You type cal. This month comes back. cal -3 prints last month, this month, next month. cal 2026 prints the year. It is not date. Date reads the clock. It is not timezone. Timezone sets the clock zone.

Practice cal in home

SSH in. Make sure home is where you sit:

pwd

You want a path that ends in your login name. If not:

cd ~

Ask for this month:

cal

You want a month grid, then the prompt back. That is enough for tonight. Practice only in home.

Debian and Ubuntu usually already have cal (ncal). Don't make apt the job.

Useful extras, still home only

Optional: three months:

cal -3

Optional: the year 2026:

cal 2026

Don't make those required. You can stop at cal.

What this is not

This is not date. That is see what time the computer thinks it is. It is not timezone. That is set the clock to your house. It is not time. That is see how long a command took. It is not timeout. That is stop a command after a few seconds. It is not whoami. That is see the login name. It is not opening SSH to the internet. That is keep the computer on the house network. Don't forward port 22.

What next

Need the clock? See what time the computer thinks it is. Need the login name? See the login name. Need how long a command took? See how long a command took. Keep SSH on the house network: keep the computer on the house network. Don't forward port 22.

Skip

  • Skip if SSH still fails. Finish SSH from the couch first.
  • Skip date, timezone, time, and timeout as tonight's job. Those pages already exist.
  • Skip setting the clock tonight. Tonight you take a look at the month grid.
  • Skip files under /etc, SSH folders, or paths you don't own. Practice only in home.
  • Skip rm -rf. Careful delete only: delete a file carefully.
  • Skip opening SSH to the internet so you can do this from a coffee shop. That is keep the computer on the house network. Don't forward port 22.

Sources

Debian: cal(1). Ubuntu: cal(1). Official pages only. For the login, see SSH from the couch. For the clock, see see what time the computer thinks it is.
