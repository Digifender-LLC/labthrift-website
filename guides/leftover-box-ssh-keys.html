Notes / Faster network / Log in with a key, not the password every time

Written 25 Aug 2026. This is a how-to, not a product card.

Log in with a key, not the password every time

After password SSH works for a while, put a key on your laptop so the computer trusts that laptop. Keep the password as a backup at first.

Password login from SSH from the couch should already be boring. The password should already be one you chose. That is change the login password. A key is a small file on your laptop that proves it is you. You type a passphrase once, or not, instead of the password every time.

Skip until password SSH is boring

If SSH from the couch still prints Permission denied, or the password is still wrong some days, stop. Fix that first. A key will not help a login that does not work yet. If SSH refuses because the computer looks different after a reinstall, that is when SSH says the computer looks different.

What a key is

You make two files. The public key goes on the computer. The private key stays on your laptop. The computer checks the public file and lets that laptop in. Never email the private key. Never copy it onto a stick you will lose. This is not a new router. The house number stays the same. The password can still work as a backup.

Make a key on your laptop

On Windows, use Windows Terminal or PowerShell. On a Mac or Linux, use Terminal. Same command:

ssh-keygen -t ed25519 -C "laptop"

Accept the default path when it asks. A passphrase on the key is optional. A short one is still better than none, so a stolen laptop file is not a free login. If you skip the passphrase, press Enter at that prompt. It writes two files under .ssh in your home folder. One ends in .pub. That is the public key.

Copy the public key to the computer

Use the username and the number from find the computer on the house network. A reservation so that number stays put is keep the computer on the same number. Prefer this command, which asks for the password one last time:

ssh-copy-id you@that-address

Swap you and that-address the way SSH from the couch taught you.

If ssh-copy-id is missing, which happens on some Windows setups, SSH in with the password. On the computer, append the public line, the whole contents of the laptop file that ends in .pub, to ~/.ssh/authorized_keys. Don't paste the private file. Then:

chmod 700 ~/.ssh

chmod 600 ~/.ssh/authorized_keys

Try it

From the same laptop:

ssh you@that-address

It should not ask for the password. It may ask for the key passphrase, if you set one. You should see the prompt, the same as SSH from the couch.

If it still asks for the password, the public line is not on that user, or you pasted the wrong file. Check you used the username, the same number, and the .pub file, not the private one. Run ssh-copy-id again. Don't start editing server config yet.

Keep password login for now

Leave password login on. Don't turn off PasswordAuthentication. That is a later harden note. If the laptop dies, the password is how you get back in from another computer. Keep it as a backup. When typing the long address gets old, give the computer a short name on your laptop. When the key login is boring, see which laptop keys the computer already trusts, then put a key on a second computer first, then turn off password login once the key works.

What next

The password should already be one you chose. That is change the login password. Once a week, keep the computer updated. When SSH is reliable, turn on a simple firewall without locking yourself out. If Pi-hole is not up yet, that is the first useful thing on the computer. Don't forward port 22. SSH stays on the house network. That is keep the computer on the house network.

Skip

  • Skip this note if password SSH is still flaky.
  • Skip buying a YubiKey for the computer.
  • Skip fail2ban. Later is slow down password guesses on SSH.
  • Skip a new firewall appliance.
  • Skip opening the computer to the internet.
