Notes / Better Wi-Fi / Look up a site name from the computer

Written 27 Aug 2026. This is a how-to, not a product card.

Look up a site name from the computer

When a website name fails, try resolving it from the computer before you buy a mesh kit.

You already know which name server the computer is asking from see which name server the computer is using. This note asks that server to turn a site name into a number. Resolve is that lookup. If ping to a number works but the name fails, this is the look.

Skip until SSH works

If you have never logged in from the couch, that is SSH from the couch. If you never installed Pi-hole, start with the first useful thing on the computer. Prefer this look after you know which name server the computer is asking: see which name server the computer is using. If even a number past the router fails, fix that first: check that the computer can reach the internet. This note assumes you can log in from the couch, or sit at the keyboard.

What this is

A look, not a shopping trip. If the computer can ping 1.1.1.1 but cannot look up a site name, that is DNS, not a dead access point. Check the lookup before you buy a mesh kit. You are not buying Omada, UniFi, or a Protectli tonight.

Look up a name

SSH in from the couch, or sit at the keyboard, then run. Replace example.com with the site that failed:

resolvectl query example.com

A number back means names work from the computer. Timeout, SERVFAIL, or NXDOMAIN means the name server is wrong or Pi-hole is not answering. That is see which name server the computer is using or when ads come back, check the ad block.

A blocked ad name can come back as 0.0.0.0. That is Pi-hole doing its job, not a broken lookup. Try a site you actually use, not an ad tracker.

Optional older print

If you want the older one-line print:

getent hosts example.com

A number and the name on one line means the computer resolved it. Empty output means the lookup failed. Keep this light. Don't edit resolved configs tonight.

What the look means

Failed lookup means fix the pointing in point the house at the ad block, check which server the computer is asking in see which name server the computer is using, or check that Pi-hole is still answering in when ads come back, check the ad block. If even 1.1.1.1 will not ping, that is past the router: check that the computer can reach the internet. Don't buy Omada or UniFi for this look. The admin password is a different note: change the Pi-hole admin password.

What next

Which name server: see which name server the computer is using. Past the router: check that the computer can reach the internet. Ads check: when ads come back, check the ad block.

Skip

  • Skip if SSH fails. That is SSH from the couch.
  • Skip a mesh kit for a failed name.
  • Skip buying a Protectli.
  • Skip forwarding port 53.
  • Skip Proxmox tonight. That is what a VM is, and when you don't need one.
